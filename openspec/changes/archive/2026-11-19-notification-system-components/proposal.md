## Why

Система уведомлений платформы обрабатывает разнородные пользовательские и системные события (отметки «избранное», репосты, упоминания, запросы на подписку, результаты опросов, модерационные действия) через многокомпонентный конвейер. Размытие границ ответственности между синхронным API, фоновыми очередями, логикой фильтрации, хранилищем и каналами реального времени приводит к непредсказуемым задержкам, деградации производительности БД при всплесках активности и рискам доставки нежелательного контента вопреки настройкам приватности. Необходима спецификация верхнего уровня, фиксирующая этапы прохождения всех видов нотификаций через компоненты системы, их зоны ответственности и эксплуатационные ожидания.

## What Changes

Создается архитектурная компонентная спецификация сквозного конвейера нотификаций платформы:
- Описание единых сквозных этапов жизненного цикла уведомления для всех поддерживаемых типов (включая реакции, репосты, упоминания, подписки, опросы и системные предупреждения).
- Определение зон ответственности и контрактов каждого функционального компонента: Client (Web/Mobile), API & Ingestion Layer, Async Queue Layer, Notification Engine (Drop/Policy/Filter/Group), Storage Layer, Real-time Streaming, External Push/Email Gateway.
- Фиксация ожиданий и гарантий на стыках компонентов: идемпотентность обработки, защита от лавинной нагрузки, уровни изоляции очередей, гарантия отката Optimistic UI и изоляция отказов внешних провайдеров.
- Фокус на внутриинстансной обработке (Local-to-Local) без федеративных накладных расходов ActivityPub.

## Impact
- **Архитектурный контур**: Веб- и мобильные клиенты, слой API-ингестии (Puma/Rails), брокер очередей (Sidekiq/Redis), ядро фильтрации и группировки (`NotifyService`), реляционное хранилище (PostgreSQL), сервер стриминга (WebSocket/Redis PubSub), шлюз пуш-уведомлений и почты.
- **Интерфейсы и протоколы**: REST API `/api/v1/notifications`, `/api/v2/notifications`, WebSocket-стримы (`notifications`), WebPush/APNs payloads, шаблоны транзакционных писем.
- **Эксплуатационные параметры**: SLA по сквозной задержке доставки, требования к идемпотентности и политике повторных попыток (retries), приоритезация очередей.
